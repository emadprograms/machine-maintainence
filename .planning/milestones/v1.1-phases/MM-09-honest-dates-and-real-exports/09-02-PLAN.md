# Plan 9-02: CSV export

## Threat Model

| ID | Threat | Severity | Mitigation | Verified by |
|---|---|---|---|---|
| T-9-04 | CSV injection: a cell beginning `=`, `+`, `-` or `@` is executed as a formula by Excel | high | Prefix such cells with a single quote and document it | 09-02-02 |
| T-9-05 | Injection into SQL via filter parameters | high | Filters bound, not concatenated | 09-02-03 |

## Tasks

### Task 1: A CSV writer worth trusting
**File:** `starter/server.js`
`toCsv(rows, columns)` — RFC 4180: CRLF, quote any field containing `,` `"` `\r` `\n` or with
leading/trailing whitespace, double internal quotes. Prefix formula-leading cells with `'`.
BOM prepended by the route, not the writer, so the writer stays unit-testable.

**Acceptance:** a row with `a,b` / `say "hi"` / `line1\nline2` round-trips through a parser to the
same three values.

### Task 2: Two export routes sharing the list query
**File:** `starter/server.js`
`GET /api/export/work-orders.csv` (`?status=`, `?equipment_id=`) and
`GET /api/export/parts.csv` (`?low=1`). Factor the WHERE-building so the list route and the export
route call the same function — the requirement is that the download matches the screen.

**Acceptance:** `?status=open` returns only open orders; `?low=1` returns only parts at or below
their reorder level.

### Task 3: Download buttons
**Files:** `starter/public/app.js`, `starter/public/index.html`
A button per screen using `window.location.href = '/api/export/....csv?...'`, passing the current
filter state.

**Acceptance:** clicking downloads a file; with a filter applied the file is narrowed.

### Task 4: Assertions
**File:** `starter/scripts/smoke-test.js`
Parse the CSV back in the test and compare values. Cover the nasty fixture, the BOM, the header
row, both filters, and a formula-leading cell.
