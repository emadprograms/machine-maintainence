# v4.0 — Stage correction and machine state

Status: completed 2026-11-05. Autonomous execution requested and completed on the session branch.

## Confirmed scope

- Redesign the work-order update dialog with more space, coherent grouping and
  responsive layout. Keep multiple parts and catalog-price defaults.
- Replace the no-change selector with a red/green machine-state toggle. Its
  default is the machine's most recently reported actual state.
- The latest explicit report or stage answer determines the machine's overall
  operating state, even when an older work order has a different answer. A newer
  reported stoppage takes it out of service. Retirement remains separate.
- Only an admin may edit or permanently delete the latest stage of a work order;
  older stages remain immutable. Editing allows time, description, photos,
  parts and the stage's running answer to be corrected.
- Reconcile stock and actual part costs transactionally on correction/deletion;
  reject an edit that consumes unavailable stock without partial changes.
  Deletion removes the stage's photos after confirmation.
- Corrected hours/costs must flow through job, machine and report totals; preserve
  reviewed final-hour baselines, old records, authentication and staged assignment.
