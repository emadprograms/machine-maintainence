## Amendment 2026-11-05 — the throttle was removed

**Decision:** record failed sign-ins; block nobody, delay nothing.

**Why.** The throttle was correct as built and wrong as product. This
application has no password reset and no second admin by default, so a block
puts a technician at a machine, unable to log a repair and unable to fix it
themselves. That cost falls on whoever needs the app most, while the benefit
falls on a threat that already required LAN access. The original requirement
asked that guessing be *slow and visible*; visibility does not require refusing
anyone, and slowness was traded away deliberately.

**What replaced it.** `starter/data/login-failures.log` — one tab-separated line
per failure with an ISO timestamp, the source address, the address attempted,
and whether the account existed. Nobody is refused; nothing is delayed. An
unknown email is recorded exactly like a wrong password so the log cannot be used
to discover which accounts exist, and the password itself is never written —
both asserted, and the password assertion was proved to fail when a fragment was
deliberately logged.

**What this costs.** Guessing is now unlimited and fast (roughly 10–20 attempts
per second against scrypt). Accepted; see AR-10-01. The control that would
actually address this is a longer password minimum, which is out of scope.

**Effect on the phase reports.** `10-VERIFICATION.md`, `10-SECURITY.md`,
`10-VALIDATION.md` and `10-01-SUMMARY.md` each carry a superseded-in-part note.
The throttle's code, tests and report are not deleted history: they were built,
they passed, and they were removed for a stated reason.

**Suite:** 145 → 138 checks. The removed assertions covered behaviour that no
longer exists; the added ones cover the behaviour that replaced it.
