# Milestone v3.0 — Context

Captured from discussion, 2026-11-06.

## The request

v2.0 made the app presentable and gave it a landing page. What it could not do was be
read back: a workshop that has been recording jobs for a month still cannot answer "what
happened to this pump", "what did we close in October", or "what did October cost". The
data is there — `closed_at` has been stored since v1.0 and never once displayed.

## The shape agreed

Three phases, each adding one thing rather than rewriting a screen:

1. **History** — a machine's own jobs, and a log of finished work with a date range.
2. **Find it** — one search box per list, composing with the filters already there, and
   exports built from the same filter so the file cannot disagree with the screen.
3. **What it cost** — labour hours per job, parts rolled up, a monthly summary.

## What was explicitly not included

Two other milestones were offered and declined on the same day:

* **Trust** — audit trail, verified off-folder backup, a rehearsed restore.
* **In the workshop** — phone layout, printable job sheet, quick actions.

Neither is a "later" commitment; both are written down only so the next milestone
conversation starts from what was actually said.

## Constraint that shaped the work

Readability is binding. Every one of the three phases had to keep the whole application
readable in one sitting, and `server.js` ended the milestone at 814 lines — past the
~600-line signal to split. That debt is recorded in `PROJECT.md` and `README.md` and is
the first thing the next milestone should address.
