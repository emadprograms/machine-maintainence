# Plan 11-01: Sidebar shell replacing the tab row

## Threat Model

| ID | Threat | Severity | Mitigation | Verified by |
|---|---|---|---|---|
| T-11-01 | Inline SVG or icon markup is built from data, allowing markup injection | medium | Icons are static strings in the module; nothing user-supplied reaches `innerHTML` | 11-01-02 |
| T-11-02 | `localStorage` throw (private mode, disabled storage) breaks the whole app on load | medium | Every access is wrapped; a failure means "expanded", not a broken shell | 11-01-03 |
| T-11-03 | A collapsed sidebar becomes unusable to a screen reader | low | Each rail entry keeps an `aria-label` and `aria-current` | 11-01-04 |

## Tasks

### Task 1: `public/shell.js`

Exports `renderShell({ pages, current, onNavigate })` and `toggleSidebar()`.

Renders a `<aside>` containing a `<nav>` of `<a>`-like buttons, one per page,
each with an inline SVG icon, a label, `aria-current="page"` when active, and a
`data-page` attribute so `showPage` can mark it. The toggle is a `<button>`
with `aria-expanded` reflecting state.

Icons: seven small SVG paths, defined in a `ICONS` object. Static strings only —
no interpolation of anything from the database.

Collapsed state read from `localStorage['mm.sidebar.collapsed']`, wrapped in
try/catch so a storage failure degrades to expanded. Applied as a class on the
`<aside>` (`.collapsed`) so CSS does the visual work.

**Acceptance:** the module's functions exist and are reachable; loading the page
renders a sidebar with seven entries for an admin.

### Task 2: Replace the tab row

**File:** `starter/public/index.html`, `starter/public/app.js`

Remove `<nav id="tabs">` and its CSS. Add `<aside id="sidebar">` before `<main>`.
`buildTabs(user)` becomes a call into `renderShell`. `showPage(key)` marks the
active entry instead of toggling button classes — same function, different
marking, so every existing caller keeps working.

The layout becomes a flex row: fixed-width sidebar, fluid content. `main` keeps
its padding but loses the 1100px cap in favour of a wider content area.

**Acceptance:** all seven screens still switch; nothing else about them changes.

### Task 3: Assertions

**File:** `starter/scripts/smoke-test.js`

- the sidebar module exists and the page no longer contains a tab row
- every page in `PAGES` has a matching sidebar entry after render (static check
  on the source, since the suite has no DOM)
- the collapsed-state key is read inside a try/catch
- every rail entry carries an aria-label (static check for the attribute)
- the toggle is a `<button>` with `aria-expanded`
- all seven loaders and every id the suite already looks up are untouched

The suite has no DOM, so these are source-level assertions. That is honest but
weaker than a rendered check; the phase verification notes it.

**Acceptance:** each assertion fails when its feature is removed.
