# Plan 13-01: Page headers and forms behind buttons

## Threat Model

| ID | Threat | Severity | Mitigation | Verified by |
|---|---|---|---|---|
| T-13-01 | A rewritten form loses an id, so a handler silently does nothing | **high** | The existing "every id looked up exists" and "every handler exists" assertions must still pass, and a new count asserts 7 forms, one per screen | 13-01-03 |
| T-13-02 | A dialog's form submits as a GET and reloads the page | medium | Every form is `<form method="dialog">` or a plain div; the existing buttons keep `type="button"` semantics via explicit handlers | 13-01-02 |
| T-13-03 | The dialog cannot be closed without JS | low | Every dialog has a close button and `<dialog>` closes on Esc natively | 13-01-02 |

## Tasks

### Task 1: A `.page-head` on all seven screens

Structure, identical everywhere:

```html
<div class="page-head">
  <div>
    <h2>Machines</h2>
    <p class="page-sub">Every machine you maintain, and what state it is in.</p>
  </div>
  <button class="primary" onclick="openForm('equipment-form')">New machine</button>
</div>
```

The purpose line is a sentence, not a label. Screens with no create action
(Due soon, Backup) keep the header and omit the button; Due soon's window
selector moves into the header's right side.

### Task 2: Each create form into a `<dialog>`

`<dialog id="equipment-form" class="sheet">` wrapping the existing card. The
inputs, their ids, placeholders and order do not change — only where they live.
Adding a shared `openForm(id)` / `closeForm(id)` in `app.js`.

**Acceptance:** no `<section data-page>` contains a `.form-grid` outside a `dialog`.

### Task 3: Assertions

- seven screens, seven page headers
- no form-grid outside a dialog
- seven dialogs, one per screen
- `openForm` exists and is called by every create button
- the pre-existing id and handler assertions still pass unchanged

**Acceptance:** each fails when reverted.
