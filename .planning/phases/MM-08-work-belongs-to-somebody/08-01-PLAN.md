# Plan 8-01: Assignment and ownership

## Threat Model

| ID | Threat | Severity | Mitigation | Verified by |
|---|---|---|---|---|
| T-8-01 | Information disclosure: the new assignable-users route leaks the full staff list (the phase-1 bug #11 returning through a second door) | high | Route returns `{ id, name }` only — no email, no role, no `active` flag | 08-01-03 |
| T-8-02 | Tampering: assigning a non-existent user id | medium | Validated against `users` before the write | 08-01-01 |
| T-8-03 | Elevation: using the assignment edit path to reach admin-only fields | medium | The PATCH accepts only an enumerated field list | 08-02-02 |

## Tasks

### Task 1: `assigned_to` column
**File:** `starter/db.js`
`assigned_to INTEGER` in the `work_orders` CREATE TABLE (no FK clause — SQLite cannot add one by
`ALTER TABLE`, and the app validates), plus `ensureColumn('work_orders','assigned_to','INTEGER')`.

**Acceptance:** existing databases gain the column on start and keep their rows.

### Task 2: `GET /api/users/assignable`
**File:** `starter/server.js`
Returns `SELECT id, name FROM users ORDER BY name` for **any signed-in user**. Deliberately
separate from `GET /api/users`, which stays admin-only.

**Acceptance:** admin 200, technician 200, and the payload contains exactly `id` and `name` keys.

### Task 3: Assignment in `POST` and `PATCH`
**File:** `starter/server.js`
`POST` accepts `assigned_to`. `PATCH` accepts `assigned_to` and `title`, both with `??`-style
fallbacks. `assigned_to: null` unassigns. Validate a supplied id exists.

**Acceptance:** assign → list shows the name; `{assigned_to:null}` → list shows null; `{assigned_to:99999}` → 400.

### Task 4: List query resolves the owner
**File:** `starter/server.js`
`GET /api/work-orders` joins `users` and returns `assignee_name`, with no filter on `active`.

**Acceptance:** a disabled owner's name is still returned.

### Task 5: Owner column and assignment dropdown
**Files:** `starter/public/index.html`, `starter/public/app.js`
Add an Owner column; add a `<select>` of assignable names to the inline edit row.
**Acceptance:** an unassigned order shows muted "unassigned"; selecting a name and saving persists it.

### Task 6: Assertions
**File:** `starter/scripts/smoke-test.js`
Assign, reassign, unassign, unknown id → 400; owner name present; disabled owner still named;
assignable route hides email; technician reaches assignable but not `/api/users`.
